This page records changes verified in the current source tree. It is not a promise that unreleased behavior is available on every deployed instance.

Public regional hosts may lag this documentation. Hosts that have not rolled 2.21.0 return **404** for `/model/facts` and `/retrieve/conflicts` because those routes are not on that build. That 404 is not the 2.21.0 contract. See [Regional API hosts](/v2/reference/regional-hosts).

## 2.21.1

Spreadsheet import/query (off by default), Explore overview-link snapshots, and hosted MCP OAuth sign-in. Verified against [brainapi2 2.21.1](https://github.com/Lumen-Labs/brainapi2). Plain-language feature pages live under [Concepts](/v2/concepts).

- `.xlsx` / `.csv` import as workbooks when `SPREADSHEET_EXPERIMENT_BRAINS` includes the brain (or `*`). Empty disables every brain. PostgreSQL only. Direct upload: `POST /ingest/spreadsheets`. See [Ingestion](/v2/concepts/ingestion#spreadsheets-experimental-opt-in).
- Explore overview snapshots store capped `overviewLinks` (4000) plus `overviewLinksTruncated`. See [Retrieval](/v2/concepts/retrieval).
- Hosted MCP OAuth: consent `request_id`, encrypted brain PATs, 303 redirect. System PAT cannot grant OAuth. See [MCP and OAuth](/v2/concepts/mcp).

## 2.21.0

Knowledge-graph memory: expert verification, cross-source conflict detection, fail-closed as-of retrieve, validity changelogs, staged-ingest rollback, and Cypher hardening. Defaults are unchanged: raw Cypher is read-only, `CONFLICT_DETECT_ON_INGEST` and `CONFLICT_DETECT_LLM` are off, as-of lookups fail closed, and ingest staging is not required for a normal import.

Deferred in this tag: agent-first MCP remember/recall/correct/check, Celery Redis reconnect, and hosted MCP OAuth.

### Verification

- Facts carry `unverified` / `verified` / `rejected` with append-only history. REST: `GET`/`POST /model/facts…`. MCP: `verify_fact`, `reject_fact`, `reset_fact_verification`, `list_facts_by_verification`, `get_fact_verification`. See [Fact verification](/v2/retrieval/verification).
- Writes require the `verification` token scope (not granted by default). `method=verified_side` conflict resolve uses the same scope.
- `verified_side` snapshots verification properties before writes. On reject failure it restores exact prior state with a history entry tagged `rollback` and keeps the conflict open. A pre-read miss or error aborts before any write.
- Rejected facts are hidden from retrieve/search/traverse unless `include_rejected=true`. `VERIFIED_FACT_RANK_BOOST` defaults to `0.15`.
- Resolved token scopes are cached for 30 seconds.

### Conflicts

- Cross-source conflict scan, list, report, resolve, dismiss. REST under `/retrieve/conflicts`. MCP: `list_conflicts`, `get_conflict`, `resolve_conflict`, `dismiss_conflict`, `conflict_report`. See [Conflicts](/v2/retrieval/conflicts).
- `POST /retrieve/conflicts/scan` returns **202** with `task_id`. The body may set `use_llm` only; it cannot override `CONFLICT_DETECT_MAX_RELATIONSHIPS` (default `10000`; `0` unlimited).
- Capped scans page by whole comparison groups, persist a rotating per-brain cursor, and wrap around. Hitting the cap sets `truncated` and stale-closes only loaded groups.
- Optional ingest/LLM detection stays off: `CONFLICT_DETECT_ON_INGEST=false`, `CONFLICT_DETECT_LLM=false`.

### As-of retrieve and changelogs

- Retrieve/search accept `as_of`. Undated facts are omitted (fail closed) and counted in `validity_unknown_count`; `include_validity_unknown=true` returns them separately. MCP as-of is on `search_semantically` only. See [As-of retrieve](/v2/retrieval/as-of).
- Changelogs: `GET /retrieve/changelogs`, `GET /retrieve/changelogs/{id}`, `GET /retrieve/changelogs/types`. MCP: `list_changelogs`, `get_changelog`. `since` is inclusive; `until` is exclusive.

### History, sources, and purge

- History-mode triggers keep original revisions; ranking cost is capped.
- Retrieve prefers the newest copy of an app source; `list_source_versions` lists versions.
- Confirmed `POST /tasks/{task_id}/purge` removes one import’s owned graph data.

### Staged ingest and rollback

- Settlement failures are bounded (5); leftover cleanup is retried. Live staged units roll back when publish settlement is exhausted.
- Graph rollback distinguishes created vs reused items and keys `rollback_done` as `{operation_id}:{kind}:{uuid}` so a later retouch cannot skip deleting the original create.

### Graph store and Cypher

- Identifier interpolation is allowlisted; raw Cypher stays read-only unless `GRAPH_RAW_WRITE_ENABLED=true`.
- `remove_nodes` decodes driver records via `Record.get`; extra invalid labels no longer drop the node.

### Defaults (unchanged unless you opt in)

| Flag / setting | Default |
| --- | --- |
| Raw Cypher | read-only |
| `GRAPH_RAW_WRITE_ENABLED` | `false` |
| `CONFLICT_DETECT_ON_INGEST` | `false` |
| `CONFLICT_DETECT_LLM` | `false` |
| `CONFLICT_DETECT_MAX_RELATIONSHIPS` | `10000` (`0` = unlimited) |
| As-of missing valid-time start | fail closed (omit; count as unknown) |
| `include_validity_unknown` | `false` |
| Token scope `verification` | not granted by default |
| `VERIFIED_FACT_RANK_BOOST` | `0.15` |
| `SEARCH_ENABLED` | `false` |

### Known issues

- Neo4j validity index count grows as 7 × the number of relationship types.
- Changelog `MATCH (n)-[r]->(m)` with OR/regex timestamp filters likely still scans relationships despite the new indexes. Needs `EXPLAIN`/`PROFILE` on a real brain; follow-up is stamp normalization at write time or typed `UNION` queries.
- `set_fact_verification` commits then re-reads; a raising re-read can leave a rejected loser in place while reporting failure without `rollback_failed`.
- Verified-side rollback is an unconditional SET by UUID and can overwrite a concurrent verification that landed after the snapshot.
- If a restore callback raises mid-loop, later facts (including the winner) may not be restored.
- REST/MCP conflict-resolve errors can include pre-read exception text; logs should stay detailed, callers should get a fixed message.
- Cold-start index setup is not serialized per database (`CREATE RANGE INDEX IF NOT EXISTS` stays correct; overlapping first callers repeat work). A raw Cypher write during type listing can wait until the next TTL for a new type’s indexes.
- Neo4j Community Edition still shares the default `neo4j` database when `CREATE DATABASE` is unsupported.
- A missing, null, or non-boolean LLM `contradicts` field is treated as `false` and can stale-close as `llm_compatible`.
- Compact timed stamps (`2024-01-01T090000`) collapse to date-only in `normalize_date_string`, so same-day events that differ only by time can share an identity UUID. Conflict detection uses `parse_date_string` and is not affected.
- An in-flight LLM verdict can stale-close a conflict after a later scan has already refreshed it with new fact values (`if_status=open` only).
- LLM batch indexes are not bounded to the current batch; a negative index can overwrite an earlier batch's verdict.
- `Config.conflict_detect_max_relationships` uses `int(...)` with no fallback; a blank or non-numeric env value raises at import. Runtime `conflict_detect_max_relationships()` already falls back.
- Compact clocks with a space separator (`20240101 090000`) compare as dates, not instants. `_instant_key` also drops microseconds, so fractional-second instants compare equal.
- Compact `as_of` values like `2024-01-01T930` can parse as 09:03 instead of being rejected.
- A comparison group larger than `CONFLICT_DETECT_MAX_RELATIONSHIPS` is still loaded whole so groups are never split.
- Truncated stale-close lists all open conflicts, then filters to scanned groups in Python.
- Skip/limit-only `list_validity_relationships` backends fall back to their native first page when no cursor is set. Production Neo4j, NetworkX, and search-fallback scans already order by comparison-group key.
- Neo4j conflict-scan count queries still run on each page (full-brain total, not the current window).
- Unknown-side lookups during stale-close are unbounded.
- The `search_relationships` fallback loads the whole graph before sorting and applying the cap.

## 2.20.1-dev.9

### Retrieval

- `POST /retrieve/context` accepts optional `include_history`. When the field is omitted, history is chosen by embedding similarity to example questions in several languages. A missing embedding stays on the current copy.
- History loads superseded source copies for the sources already in the result and labels them `[superseded]`.

### MCP

- `list_changelogs` and `get_changelog` read graph changelog entries.
- `list_source_versions` reads the current copy and previous copies of a source.
- `traverse_graph` still returns the full walk and also lists superseded relationships in `invalidated`.

## 2.17.0-dev

### Search and retrieval

- Added opt-in ranked Search with BM25, dense, graph, catalog, plugin, reranking, personalization, facets, and stage profiling controls.
- Added Search Rerank, Search SPLADE, and Search ColBERT plugin documentation and author hooks.
- Clarified that `/retrieve/context`, `/retrieve/search`, `/retrieve/recommend`, graph APIs, and MCP are distinct surfaces over one knowledge base.
- Added query-gated catalog personalization and documented safe fallback behavior.

### Ingestion and recommendations

- Documented direct and event-centric structured triples, deterministic/hybrid/enrich modes, and `skip_enrichment`.
- Documented behavior weights and the additive Features Rec and RecSys GNN plugin paths.

### Developer experience

- Reorganized V2 into task-first Start, Build, Retrieve, Extend, Operate, and Reference groups without changing established URLs.
- Added a complete quickstart, authentication/brain-scoping guide, retrieval chooser, configuration guide, troubleshooting hub, and grouped core API reference.
- Kept benchmark and incomplete placeholder pages unpublished across HTML and machine-readable surfaces.
