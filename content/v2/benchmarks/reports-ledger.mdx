`benchmarks/REPORTS.json` is the shared BrainAPI results ledger. Successful `evaluate` / `report` runs upsert their suite entry when the report status is `ok`.

## Schema

| Field | Meaning |
| --- | --- |
| `schema_version` | Ledger format version (`2` as of current tree) |
| `updated_at` | ISO timestamp of last successful upsert |
| `description` | Human summary of the file |
| `benchmarks.<suite>` | Per-suite object with `name` + `leaderboard` |

Suites: `locomo`, `longmemeval`, `beam`.

## Leaderboard entries

Each suite stores a `leaderboard` array. Common fields:

| Field | Suites | Notes |
| --- | --- | --- |
| `run_id` | all | Directory under `runs/` |
| `track` | all | e.g. `sota`, `product` |
| `scope` | all | e.g. `conv-26`, `1M/1` |
| `headline_judge_accuracy` / `_pct` | LoCoMo | Judge accuracy fraction / percent |
| `headline_score` | BEAM | Continuous `[0,1]` mean of ability scores |
| `answer_model` / `judge_model` | all | Models used for the claim |
| `brain` | all | Brain id measured |
| `git_sha` | all | Code under test |
| `report_path` | all | Path to `report.json` |
| `recorded_at` | all | When the ledger row was written |

## What belongs on the board

- Successful scored runs (`status: ok`)
- Real metrics — skip failed/junk runs, nonsense 0% scores, and broken manifests
- Upsert by `run_id` under the suite (harnesses do this automatically via `write_report`)

If you patch `runs/<id>/report.json` by hand, update `REPORTS.json` yourself with the same schema.

Research caveats and checkpoint narrative stay in local notes (e.g. `runs/CHECKPOINT_NOTES.md`), not in the ledger.

## Adding a suite

1. Add `benchmarks.<suite_id>` with `name` + `leaderboard: []`.
2. Wire the harness `write_report` path to upsert the same way as LoCoMo/BEAM.
3. Document the suite under [Benchmarks](/v2/benchmarks).
