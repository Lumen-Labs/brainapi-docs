BrainAPI supports the MCP protocol. You can use MCP with BrainAPI or with your remote deployed BrainAPI instance.
There are several ways to connect, you can use your client of choice to connect to the MCP server.

Looking for documentation tools instead? Use the separate [Docs MCP](/v2/agentic/docs-mcp) at `https://brainapi.lumen-labs.ai/docs/mcp` (search + markdown fetch). The rest of this page covers the **product** MCP on your API host.

## Connect Claude Desktop

Claude Desktop uses a local stdio process, while BrainAPI exposes MCP over HTTP. Connect the two with either the Node.js adapter or the pre-built BrainAPI bridge.

### 1. Open the configuration file

In Claude Desktop, open **Settings**, select **Developer**, and choose **Edit Config**. Using the button avoids relying on an operating-system-specific or user-specific file path.

### 2. Choose one bridge

If `npx` is available on Claude Desktop's process path, add the Node.js adapter:

```json
{
  "mcpServers": {
    "brainapi": {
      "command": "npx",
      "args": [
        "-y",
        "@pyroprompts/mcp-stdio-to-streamable-http-adapter"
      ],
      "env": {
        "URI": "http://localhost:8001/mcp",
        "MCP_NAME": "brainapi",
        "BEARER_TOKEN": "brainpat_replace_me"
      }
    }
  }
}
```

Alternatively, download the bridge from the [BrainAPI MCP bridge release](https://github.com/Lumen-Labs/brainapi2/releases/tag/mcp-bridge-v0.1.0) and configure its absolute executable path:

```json
{
  "mcpServers": {
    "brainapi": {
      "command": "/absolute/path/to/brainapi-mcp-http-adapter",
      "args": [],
      "env": {
        "URI": "http://localhost:8001/mcp",
        "MCP_NAME": "brainapi",
        "BEARER_TOKEN": "brainpat_replace_me"
      }
    }
  }
}
```

Replace the example URL and PAT locally. Never commit the resulting configuration or share a screenshot containing its token or local file path.

### 3. Restart and verify

Save the file and restart Claude Desktop. The configured `brainapi` server should appear in the MCP tools list. If it does not, verify that the bridge command runs in a terminal, the URL ends in `/mcp`, and the PAT can access the intended BrainAPI instance.

## Graph, changelog, and versions

These reads are on the product MCP, alongside semantic search and `search_memory`.

- `traverse_graph` walks the live graph from a start node. The response keeps every hop and also lists superseded relationships in `invalidated` when a relationship property includes `invalid_at` or `deprecated`.
- `list_changelogs` lists graph changelog entries, newest first. Filter with `query_text`, a changelog type, and optional `since`/`until`. `get_changelog` reads one entry by id.
- `search_semantically` accepts `as_of` and `include_validity_unknown`. `search_memory` and `traverse_graph` do not.
- `list_source_versions` returns the current copy and previous copies of a source. Pass `source_key`, or a query when the key is unknown. The query is used only to find the source. If embedding fails, the tool returns an error and no versions.

## Verification and conflicts

These tools sit on the product MCP alongside the graph reads above.

- `list_facts_by_verification` and `get_fact_verification` read expert verification state. Default listing hides rejected facts unless `include_rejected` is true or `state` is `rejected`.
- `verify_fact`, `reject_fact`, and `reset_fact_verification` require the `verification` token scope. Actor identity comes from the authenticated token; `verified_by` is ignored.
- `list_conflicts`, `get_conflict`, `resolve_conflict`, `dismiss_conflict`, and `conflict_report` manage cross-source conflicts. `method=verified_side` also requires the `verification` scope. Start a scan with REST `POST /retrieve/conflicts/scan`; there is no MCP scan tool.

See [Fact verification](/v2/retrieval/verification) and [Conflicts](/v2/retrieval/conflicts). Raw Cypher through MCP stays read-only unless `GRAPH_RAW_WRITE_ENABLED=true`.
